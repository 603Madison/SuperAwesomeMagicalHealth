## SuperAwesomeMagicalHealth 0.10.1: a security review, and its fixes

The whole app was reviewed for security: the server, the web and phone apps, the watch app, the
release process and the deployment files. Nothing serious turned up. Everything found is fixed here.
Update the server and the app.

**Fixed (Medium)**
- **Password guessing:** many guesses sent at the same moment could all slip past the sign-in
  limits. Each guess is now counted before it's checked.
- **Memory:** someone with an account could make the server run out of memory, by connecting
  "Mealie" to a server that sends huge compressed answers. Every outside service's answer is now
  read only up to a limit.
- **Reminders:** someone with an account could hold up everyone's reminders, dose reminders
  included, with slow browser notification sign-ups. Notifications now go out in the background with
  short time limits, and each person has at most 10 browsers.
- **Connector links:** two troubleshooting tools let a link see hints of private features it
  wasn't given (dose reminders, bladder training and the like), and the full addresses of webhooks.
  They now leave those out and show only each webhook's host.

**Fixed (Low)**
- **Server data:** the data folder sits inside the code folder when you run it with Compose. It's
  now ignored by git and kept out of images, so the database and its key can't be committed by
  accident. It's also readable only by the server.
- **Release process:**
  - the app's signing key is only on disk for the signed build, not while the tests run;
  - server images are published only after the release checks pass;
  - versions are checked.
- **App sign-in:** the app and the sign-in page now show the same pairing code. Check they match, so
  another app on your phone can't get itself signed in.
- **Period patterns:** these could show up in Autism & ADHD and Symptoms for someone you shared
  those with, or a link given them, without the cycle. They're now left out unless the cycle is
  shared too.
- **Assistant:** after it has read food names from other databases in a reply, it logs only food,
  so hidden words in a recipe name can't get it to mark a dose taken.
- **Single sign-on:** browsers signed in this way now sign in again within a month, so someone
  removed at your identity provider doesn't stay signed in here.
- **Home networks:** webhooks and Mealie reaching home networks is now off on new servers, and the
  admin switch says what it allows. Your server keeps its setting.
- **Smaller fixes:**
  - signing out with a lowercase "bearer" now really signs out;
  - test emails are limited and no longer show the mail server's details;
  - "Update now" on medical records can't be spammed;
  - health data is never kept in a browser's cache;
  - the error after a portal sign-in can't be made to say other words;
  - placeholder admin passwords from examples are refused;
  - vitals targets aren't shared without Vitals;
  - webhook logs carry ids, not names.
